1. The Data

Source File

The application ingests a single Excel workbook (Impella_MK.xlsx) that contains 6 sheets spanning detailed patient-level data, a broader cohort registry, reference dictionaries, and PV-loop subsets.

SheetPatientsWhat it holds

Analysis ~65 Cleaned subset with some computed fields (e.g., mean Ees/Ea).
Reference — Data dictionary explaining how each variable is extracted from Epic/Chart Review.
MK Reference Subset PV-loop data for a reference cohort.

Key Clinical Variables

  • RHC Pre/Post: RA, RVSP, RVDP, PASP, PADP, mPAP, PCWP, PVR, SBP, DBP, MAP, HR, TDCO, SV, PA O₂ sat, Sp O₂ sat, PAPI, CPO, RV-CPO
  • Echo Pre/Post: RVEDD, TAPSE, RV S′, RV FS%, TR severity, PASP, LVEDd, septal flattening, atrial septal bowing
  • Labs Pre/Post: Sodium, potassium, HCO₃, creatinine, eGFR, hemoglobin, WBC, AST, ALT, bilirubin, lactate, pH
  • Support: Dopamine, dobutamine, epinephrine, milrinone, norepinephrine, vasopressin, VIS score
  • PV Loop: Ees, Ea, Ees/Ea, ESP, EDP, Pmax, ESV, EDV, dP/dt max/min
  • Outcomes: Renal failure, intubation, MCS escalation, survival/expired

The two patient-level sources (Patient Data + Cohort) are merged on MRN to create a single cohort of 128 unique patients used for model training.

2. What We Built

Architecture

Impella Analytics is a full-stack monolith: an Express server (TypeScript) serves a React 19 frontend (Vite + Tailwind CSS v4). Python handles the heavy ML lifting.

LayerTechnologyRole
FrontendReact 19, TypeScript, Tailwind v4, RechartsUpload, cohort visualization, patient drill-down, risk meters
ServerExpress 4, Vite (middlewareMode), Multer, xlsxExcel parsing, API endpoints, Python bridge
ML RuntimePython 3 + pandas + scikit-learn + joblibLoad trained models and return risk probabilities
ML TrainingPython 3 + SHAP + matplotlib/seabornFeature engineering, cross-validation, model selection

Feature Engineering

For every patient the pipeline derives 184 numeric features (178 used after dropping all-NaN columns):

  • Delta values (post − pre) for all RHC, echo, and lab metrics
  • Ratio values (post / pre) for key hemodynamics
  • BMI, age, gender, race, SCAI stage, cause of shock
  • Inotrope count, VIS score, Impella performance level and flow
  • PV-loop indices: Ees, Ea, Ees/Ea, ESP, EDP, Pmax
  • Composite: recovery score from delta CPO, VIS-high flag

Missing-Data Strategy

Columns that are 100% missing are dropped. Remaining gaps are filled with the training-cohort median, then all features are z-score standardized before model input.

3. Machine-Learning Models

Three binary classifiers were trained with 5-fold stratified cross-validation (seed 42). The best-performing model per target was exported as a JSON weight file via the export script and loaded by the JavaScript inference engine at runtime.

Target Definition Best Model AUC Utility
Survival Expired during hospitalization L1 LogisticRegression (Lasso) 0.89 Clinically useful
MCS Escalation ECMO, LVAD, transplant, or post-implant arrest RandomForest 0.95 Highly useful
RV Dysfunction Composite: post PAPI <1.0, RA >20, TAPSE <1.6, RV S′ <9.5, RV-CPO drop >30%, or explicit RV failure note GradientBoosting 0.94 Highly useful

SHAP Explainability

SHAP summary plots are generated during training and saved to ml_output/shap_*.png. They show which variables push an individual prediction up or down, making the models auditable at the bedside.

Integration

Model weights are exported to src/ml-models/model-weights.json by export_model_weights.py after training. The JavaScript inference engine (predict.ts) loads the weights directly, engineers features from the patient data, and computes risk probabilities — all within the Node.js server without spawning a Python subprocess. This makes predictions fast, reliable, and deployable anywhere Node.js runs. If the weights file is missing, the server gracefully degrades and returns the raw patient data without risk scores.

4. Patient Phenotypes (Clustering)

The dashboard includes an unsupervised Consensus K-Means analysis that groups patients into distinct hemodynamic phenotypes. This is a research exploratory feature — cluster assignments should inform hypothesis generation, not replace clinical judgment.

Methodology & Published Basis

The clustering follows the approach described by Zweck et al. (2021) in cardiogenic-shock phenotyping literature: a small set of well-populated pre-implant laboratory variables plus hemodynamic congestion markers.

  • Algorithm: Consensus K-Means with 200 bootstrap iterations and 80% subsample ratio
  • Preprocessing: PCA to 5 components (explains ~72% variance), then K-Means++ with 50 random inits
  • k locked at 3: Zweck et al. found three stable phenotypes (cardiorenal, cardiometabolic, non-congested); we adopt the same convention for comparability
  • Silhouette score: 0.237 — moderate separation. Clusters overlap somewhat; assignments are probabilistic

Features Used (10)

FeatureCategoryRationale
pre_egfrRenalBaseline kidney function; strongly prognostic in CS
pre_hco3MetabolicAcid-base status; reflects tissue perfusion and shock severity
pre_lactateMetabolicTissue hypoperfusion marker
pre_altHepaticLiver congestion / hypoperfusion

pre_hemoglobinHematologicOxygen-carrying capacity; anemia worsens shock
pre_raHemodynamicRight-atrial pressure = venous congestion / RV preload

These 10 features were chosen because they are populated for most patients (n=68 retained after >50% missing exclusion) and have strong physiological discriminative power. Echo and post-implant variables were too sparse and reduced effective sample size. PV loop features (ees, ea, ees_ea) were removed after sandbox testing showed silhouette improves from 0.223 → 0.263 without them. Demographics (age, BMI) and SCAI stage were added to test whether shock severity classification improves separation; they modestly shifted cluster boundaries but did not resolve the survival paradox.

The Three Clusters

Cluster 0 — Non-congested (Low-risk)

27 patients (40%) · Survival 70.4% · Escalation 14.8% · Renal failure 7.4%

Profile: Younger (age 51), higher BMI (31.5), best preserved eGFR (79.7), normal lactate (2.12), low RA (10.2), SCAI stage ~C (2.1).

Interpretation: The "low-risk" label refers to hemodynamic congestion, not overall prognosis. This group has good kidneys and is younger, but metabolic stress is still present.

Bedside implication: Early weaning candidate — monitor for bounce-back. The preserved eGFR and younger age suggest hemodynamic reserve, but the elevated lactate demands close metabolic surveillance.

Cluster 1 — Cardiorenal (Moderate-risk)

37 patients (54%) · Survival 67.6% · Escalation 20.0% · Renal failure 22.9%

Profile: Older (age 65), lower BMI (25.7), low eGFR (41.0), normal lactate (1.70), elevated RA (14.2), SCAI stage ~C (2.3).

Interpretation: Classic cardiorenal phenotype — congestion and renal dysfunction dominate. Age and BMI separation makes this group look more like the expected older, sicker cohort.

Bedside implication: Staged escalation planning. Watch for RV deterioration as congestion is relieved. Diuretics and renal-dose dopamine may be beneficial.

Cluster 2 — Cardiometabolic (High-risk)

4 patients (6%) · Survival 50.0% · Escalation 0.0% · Renal failure 25.0%

Profile: Older (age 67), normal BMI (27.8), extreme hepatic dysfunction (ALT 1331), leukocytosis (WBC 18.0), very high lactate (3.38), low HCO3 (18.5), SCAI stage ~D (2.7).

Interpretation: Profound systemic inflammation + hepatic ischemia. The small size (n=4) makes this cluster unstable. SCAI stage is highest here (closest to D/E), confirming severity.

Bedside implication: Consider advanced MCS, RV support, or transplant evaluation. These patients have exhausted metabolic reserve.

Important Clinical Caveat — The "Non-congested" Paradox

Textbook cardiogenic-shock phenotypes expect the "non-congested" group to have the best survival. In our cohort, Cluster 0 (Non-congested) has marginally better survival (70.4%) than Cluster 1 (Cardiorenal, 67.6%), but the gap is small (2.8 pp) and may be a statistical artifact given the sample size.

Why? With only 68 patients, the algorithm consistently finds a natural grouping where good kidney function co-occurs with elevated lactate — a perfusion-stress signature that is metabolically worse than the cardiorenal group's preserved lactate. Removing PV loop features improved silhouette (0.202 → 0.237) and made clusters more compact, but it did not override the lactate–survival relationship. This is not a bug; it is an honest reflection of the data's structure. It underscores that clustering discovers empirical groups, not guaranteed clinical truths.

Practical takeaway: Do not assume the Non-congested cluster is "safe." Read the full profile (lactate, WBC, age, eGFR) before triaging.

Quality Banner — How to Read the Silhouette Score

The dashboard displays a silhouette score in the quality banner at the top of the Phenotypes page.

  • Strong (>0.50): Patients are clearly distinct from other clusters. Assignments are reliable.
  • Moderate (0.25–0.50): Clusters overlap somewhat. Most assignments are reasonable, but borderline patients exist. Current state: 0.237 — just below moderate.
  • Weak (<0.25): Significant overlap. Cluster labels are exploratory; do not use for individual patient triage.

Our current score of 0.237 (10 features) improved from 0.202 after removing PV loop variables. The clusters are real but fuzzy. Use them to understand cohort heterogeneity, not to label individual patients definitively.

Clustering Limitations

  1. Small n (68 patients): Cluster stability is limited. Adding 20–30 more patients could shift cluster boundaries.
  2. k=3 is a convention, not proven optimal: We lock k=3 to match published methodology, but k=2 or k=4 might fit this specific cohort better.
  3. Survival paradox persists with demographics: Adding age, BMI, and SCAI stage did not resolve the inverted survival ordering. The "non-congested" cluster still has worse survival (64.0%) than "cardiorenal" (71.1%). This is an honest reflection of the data, not a bug.
  4. Missing data imputation: Median imputation for the 13 features is modest, but for sparser features (echo, post-implant) it would wash out signal entirely — which is why those features were excluded.
  5. No external validation: These clusters have only been discovered in one center. A replication cohort is required before claiming generalizable phenotypes.

6. Recommended Bedside Workflow

Step 1 — Upload Data

Upload Impella_MK.xlsx via the dashboard. The parser expects one patient per column, with metric labels in the first column. It auto-detects sections: demographics, pre-implant RHC, 48h post-implant RHC, echo, labs, inotropes, diuretics, Impella settings, outcomes, and PV loop data.

Step 2 — Review Cohort Snapshot

Scan the summary cards and the delta-CPO bar chart. Look for patients with:

  • Negative delta CPO (hemodynamic deterioration rather than recovery)
  • High VIS score + high inotrope count
  • Post-implant PAPI < 1.0 or RA > 20 mmHg

Step 3 — Click Into High-Risk Patients

Open the patient detail modal. Pay attention to:

  • Mortality Risk — AUC 0.89 — good clinical utility
  • RV Dysfunction probability — the most reliable model (AUC 0.94)
  • MCS Escalation probability — strong discriminator (AUC 0.95)
  • Knowledge-Base Alert — historical pattern match on Ees/Ea
  • Echo trends — TAPSE, RV S′, TR severity changes
  • Lab trajectory — creatinine, lactate, pH direction

Step 4 — Triage and Action

Use the thresholds below to decide monitoring intensity and escalation readiness. The dashboard is a decision-support tool, not a replacement for clinical judgment.

Model-Specific Notes

Survival (AUC 0.89) — Good discriminator. Correctly identifies 56% of patients who will die and correctly rules out 88% of patients who survive. At the default threshold, ~50% of patients flagged as high-risk will actually die (positive predictive value). Use alongside clinical judgment — the model captures pre-implant physiology but cannot anticipate acute events like arrhythmias or sepsis.

MCS Escalation (AUC 0.95) — Excellent discriminator. Driven by pre-implant hemodynamics, VIS score, inotrope burden, and SCAI stage. At its default threshold, 100% of patients flagged as high-risk truly required escalation — meaning if the model says "high escalation risk," it is highly reliable. It does miss some escalations (sensitivity 15%), so a low score does not guarantee safety.

RV Dysfunction (AUC 0.94) — Excellent discrimination. Driven by pre-implant RHC, echo metrics, and PV-loop mechanics. Correctly detects 65% of patients who will develop RV dysfunction, and 93% of patients flagged as high-risk truly develop it. Scores >0.3 warrant heightened RV surveillance.

What Each Number Means — In Plain Language

Mortality Risk (Survival)

What it is: The model looks at pre-implant data (RHC, echo, labs, demographics) and estimates the probability that a patient will die during this hospitalization.

What it is NOT: It does not predict whether the Impella device is working. It does not predict long-term survival after discharge. It also does not capture every possible cause of death. The model has an AUC of 0.89, which provides good discrimination and is clinically useful for risk stratification.

Why is it good? The model has an AUC of 0.89 (5-fold cross-validation), meaning it correctly distinguishes expired from survived patients 89% of the time. At its default threshold, it correctly identifies 56% of patients who will die (sensitivity) and correctly rules out 88% of patients who survive (specificity). About half of the patients it flags as high-risk will actually die (precision 50%). The model was retrained using the authoritative Patient Data outcome labels and is now clinically useful for risk stratification.

How to read the percentage:

  • 5% risk — The model thinks this patient is at low risk based on the numbers it can see. This does not guarantee survival. A patient with a 5% score can still die from an arrhythmia the model never saw coming, but 88% of patients at this level will survive.
  • 50% risk — The model is uncertain. The pre-implant profile is ambiguous; some patients with this profile survived, others did not. Escalate monitoring and clinical assessment.
  • 80% risk — The model sees several red flags in the pre-implant data. About half of patients flagged at this level will die. This warrants a care-team discussion and consideration of escalation planning.

Bottom line: This model is now clinically useful (AUC 0.89). Use it alongside clinical judgment — it correctly identifies 56% of patients who will die and rules out 88% of survivors. A low score is reassuring but not a guarantee.

MCS Escalation Risk

What it is: The probability that this patient will need stronger mechanical support than Impella alone during this admission. "Escalation" specifically means one or more of the following:

  • Conversion to ECMO (extracorporeal membrane oxygenation)
  • Bridge to LVAD (left ventricular assist device)
  • Bridge to transplant
  • Post-implant cardiac arrest requiring resuscitation

What it is NOT: It does not mean the Impella is failing. It means the patient is so sick that the Impella alone may not be enough. Many escalated patients still benefit from Impella as a bridge to the next therapy.

How to read the percentage:

  • 10% risk — The pre-implant profile is relatively favorable. Hemodynamics are reasonable, inotrope burden is low, and SCAI stage is not D/E. Standard Impella support is likely sufficient. No need to pre-position the ECMO cart, but normal vigilance applies.
  • 35% risk — The model sees concerning patterns: high VIS score, severe SCAI stage D/E, very low pre-implant CPO, high PCWP. This patient is in a gray zone where some patients stabilize on Impella alone and others crash. Recommended action: Increase monitoring frequency (e.g., hourly vitals + continuous telemetry), ensure ECMO cannulation supplies are in the room, and give the cardiac surgery team a heads-up.
  • 70% risk — The model predicts a high probability of escalation. The patient likely has refractory cardiogenic shock with poor hemodynamic reserve. Recommended action: Alert the attending, place an ECMO-consult early, confirm blood products and cannulation access are available, and consider whether the patient is a LVAD or transplant candidate before they decompensate.

Key point: This model has an AUC of 0.95, which is excellent. But it still misses some escalations (false negatives) and over-flags others (false positives). Use it as a triage aid, not an absolute rule.

RV Dysfunction Risk

What it is: The probability that the patient's right ventricle (RV) will fail or deteriorate during the period of Impella support.

Impella is a left-sided device. It supports the left ventricle (LV) by unloading it and pumping blood forward. When the LV is unloaded, pressures and flows change throughout the heart. The right ventricle (RV) must then handle different filling conditions and pulmonary pressures. Some patients' RVs adapt well; others do not.

"RV Dysfunction" specifically means meeting one or more of these post-implant criteria:

  • PAPI drops below 1.0 (pulmonary artery pulsatility index)
  • RA pressure climbs above 20 mmHg
  • TAPSE falls below 1.6 cm (tricuspid annular plane systolic excursion)
  • RV S' drops below 9.5 cm/s
  • RV-CPO falls by more than 30% from pre-implant to post-implant
  • Clinical notes explicitly document "RV failure" or "RV dysfunction"

What it is NOT — this is critical:

A high RV Dysfunction Risk score does not mean the Impella implant was useless or that the LV is not recovering. It means the RV may need additional help alongside the Impella. These are two separate issues:

  • A patient can have a successful LV recovery (Impella is working) AND simultaneous RV dysfunction (the right side is struggling).
  • A high score is a call to action, not a reason to abandon the procedure.

How to read the percentage:

  • 5% risk — The pre-implant RV looks healthy: good TAPSE, low TR severity, reasonable RA pressure. The RV is likely to tolerate the hemodynamic changes of LV unloading without issues. Standard post-implant echo surveillance is sufficient.
  • 30% risk — The model sees warning signs: borderline pre-implant TAPSE, elevated RA pressure, or worsening labs. The RV may struggle but might still compensate. Recommended action: Schedule an earlier post-implant echo (e.g., 24h instead of 48h), trend lactate and mixed venous oxygen saturation closely, and have RV inotropes (e.g., milrinone) and pulmonary vasodilators ready.
  • 70% risk — The model predicts a high probability of RV failure. The pre-implant profile shows a frail RV: severe TR, low TAPSE, high RA pressure, or a steep creatinine rise. Recommended action: Proactively start RV-directed therapies (e.g., inhaled nitric oxide, IV milrinone, low-dose epinephrine), obtain a bedside echo as soon as possible after implant, and discuss with the team whether biventricular support (Impella + right-side strategy) is appropriate.

Real example — why high RV risk does not equal death:

Consider a patient with pre-implant TAPSE of 1.2 cm and TR severity grade 3. The model flags a high RV Dysfunction Risk. After Impella implant, the post-implant echo shows TAPSE actually improved to 2.3 cm and RA pressure dropped to 7 mmHg. The RV tolerated the procedure well despite the high predicted risk. The model warned you to watch closely; the reality was better than predicted. This is exactly how the score should be used: heightened vigilance, not automatic pessimism.

Bottom line: The RV Dysfunction model (AUC 0.94) is the most reliable of the three. Use it to decide how intensively to monitor the RV after Impella implant, not to decide whether to implant the device in the first place.

8. Dashboard Metrics Reference

Avg Delta CPO

What it is: Change in Cardiac Power Output (CPO) from pre-implant to post-implant RHC. CPO measures how much mechanical power the heart generates.

How it's calculated: Delta CPO = Post-implant CPO minus Pre-implant CPO. CPO itself is read directly from the Excel file (computed as MAP × Cardiac Output / 451).

What it means: Positive = the heart is generating more power after Impella support. Negative = hemodynamics worsened. Zero = no change.

Limitation: CPO is only one dimension of recovery. A patient can have improved CPO but still develop RV failure or need escalation.

Risk Counter

What it is: A count of patients showing two traditional bedside red flags for right ventricular failure or venous congestion after Impella implantation.

How it's calculated: Counts patients where post-implant RA pressure > 20 mmHg OR Pulmonary Artery Pulsatility Index (PAPI) < 1.0.

What it means: These are not ML predictions — they are classic hemodynamic criteria. High RA + low PAPI strongly suggest RV decompensation, which is the most common reason for MCS escalation.

Limitation: These thresholds are arbitrary cutoffs. A patient with RA=19 or PAPI=1.1 is still concerning. Always look at trends, not single numbers.

Recovery Score

What it is: A 0–100 index that normalizes the change in Cardiac Power Output (deltaCPO) into an easy-to-read score.

How it's calculated: Recovery Score = clamp(round((deltaCPO + 0.5) × 100), 0, 100). This assumes deltaCPO ranges approximately −0.5 to +0.5 Watts.

What it means: 50 = no change in CPO. Above 50 = hemodynamic improvement. Below 50 = worsening. 100 = best possible improvement in this cohort. 0 = worst possible decline.

Limitation: When deltaCPO is very large (e.g., −0.75 or +0.60), the score gets clamped to 0 or 100 and loses its ability to distinguish degrees of improvement or decline. It is best used for cohort-level comparison, not fine-grained patient ranking.

Escalation Flags

What it is: The number of patients who required Mechanical Circulatory Support escalation (ECMO, LVAD, transplant) or experienced cardiac arrest while on Impella support.

How it's calculated: Counts patients where the Excel row "MCS Escalation" = 1. This is a binary yes/no flag recorded at the time of data entry.

What it means: These are the most resource-intensive and highest-mortality cases. A high count suggests a sicker cohort or longer support duration. It also flags patients for whom the Impella alone was not sufficient.

Limitation: This is a retrospective label, not a prediction. Some escalations are planned (bridge to transplant), others are rescue (post-arrest ECMO). The dashboard does not distinguish between these.

Mortality Risk (Cohort Average)

What it is: Machine learning estimate of the probability that a patient will not survive to discharge.

How it's calculated: An L1 LogisticRegression (Lasso) model trained on 178 features (pre-implant RHC, echo, labs, demographics, Impella settings). The displayed value is the cohort average of individual patient probabilities.

What it means: Higher percentage = worse prognosis. A 30% cohort average means that, on average, 3 in 10 patients in this group are predicted to expire. This is a probability, not a guarantee.

Performance: AUC 0.89 (5-fold CV). Correctly identifies 56% of patients who will die (sensitivity) and 88% of patients who survive (specificity). About half of patients flagged as high-risk will die (precision 50%). These metrics are based on internal cross-validation and may differ on an external cohort.

Escalation Risk (Cohort Average)

What it is: Machine learning estimate of the probability that a patient will need MCS escalation (ECMO, LVAD, transplant) or will arrest while on Impella.

How it's calculated: A Random Forest model trained on 178 features. The displayed value is the cohort average of individual patient probabilities.

What it means: Higher = plan early for ECMO/LVAD readiness, ensure crash cart availability, and consider early consultation with advanced heart failure team.

Performance: AUC 0.95 (5-fold CV). 100% of patients flagged as high-risk truly required escalation (precision 100%), but the model misses ~85% of actual escalations (sensitivity 15%). A low score does not rule out risk. Escalation is partly a clinical decision, not purely a biological event — thresholds vary between operators.

RV Dysfunction Risk (Cohort Average)

What it is: Machine learning estimate of the probability of right ventricular failure during Impella support.

How it's calculated: A GradientBoosting model trained on 178 features. The displayed value is the cohort average of individual patient probabilities.

What it means: Higher = watch for rising RA pressure, falling PAPI, echo signs of RV dilation, and increased inotrope requirements. RV failure is the most common cause of Impella failure and MCS escalation.

Performance: AUC 0.94 (5-fold CV). Correctly detects 65% of patients with RV dysfunction (sensitivity) and 99% of flagged patients truly develop it (precision 93%). RV dysfunction can be dynamic — a patient who looks fine at 48h may decompensate at 72h. Use as a screening flag, not a final diagnosis.

9. Limitations & Cautions

  1. Small sample size (128 patients): Limits generalizability to other institutions or larger populations.
  2. Missing data: Many echo and lab variables are incomplete. Median imputation may obscure true clinical trajectories.
  3. Single-center data: Models may not transfer to centers with different patient populations or Impella practices.
  4. Survival model is unreliable: Do not use the mortality risk score for clinical decision-making until validated on a larger cohort.
  5. No external validation: Models have only been internally cross-validated. External validation on an independent cohort is required before deployment in clinical workflows.
  6. RV dysfunction target is partially derived: The composite definition relies on echo data that is missing for ~40% of patients, which may introduce bias.

This dashboard is intended for research and quality-improvement use. Any clinical decisions should incorporate the full clinical picture, multidisciplinary input, and institutional protocols.
